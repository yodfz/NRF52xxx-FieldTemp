## 一、代码架构与模块化优化

### 1.1 单文件代码过于庞大

当前所有代码都在一个 `main.c` 文件中（约3000行），建议拆分为多个模块：

| 模块文件 | 功能描述 |
|----------|----------|
| `sensors/aht30.c/h` | AHT30 温湿度传感器驱动 |
| `sensors/spl06.c/h` | SPL06-001 气压传感器驱动 |
| `storage/w25q64.c/h` | W25Q64 SPI Flash 驱动 |
| `storage/nvs_config.c/h` | NVS 配置管理 |
| `ble/ble_services.c/h` | 蓝牙GATT服务定义 |
| `ble/ble_adv.c/h` | 蓝牙广播管理 |
| `led.c/h` | LED指示灯控制 |

### 1.2 全局变量过多

### 1.4 模块化实施注意事项

⚠️ **重要提醒：**

1. **GATT 服务定义必须保留在 main.c**
   - Zephyr 的 `BT_GATT_SERVICE_DEFINE` 宏需要在编译时静态定义
   - GATT 回调函数与服务定义紧密耦合，不能轻易分离
   - 如需完全分离，需要重新设计服务注册机制

2. **模块间依赖关系**
   - `main.c` 依赖所有模块的头文件
   - 传感器模块相互独立
   - `nvs_config` 依赖 `device_config_ctx_t` 和 `storage_position_t` 结构体
   - `ble_services` 依赖 `common.h` 中的 `history_transfer_ctx_t`

3. **编译配置**
   - 已更新 `CMakeLists.txt` 添加所有新源文件
   - 添加了 `target_include_directories(app PRIVATE src)` 以支持模块间引用

4. **后续整合步骤**
   - 需要修改 `main.c` 以使用新模块的 API
   - 替换原有的函数调用为模块函数
   - 删除 `main.c` 中已迁移到模块的代码
   - 编译测试验证功能正常

5. **Flash/RAM 影响**
   - 模块化本身不会显著增加 Flash/RAM 占用
   - 每个 `.c` 文件增加少量符号表开销
   - 预计 Flash 增加 < 500 字节

```c
// 添加CRC8校验函数
static uint8_t crc8_aht(const uint8_t *data, uint8_t len)
{
    uint8_t crc = 0xFF;
    for (uint8_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; j++) {
            crc = (crc & 0x80) ? (crc << 1) ^ 0x31 : crc << 1;
        }
    }
    return crc;
}

// 在 aht30_read() 中添加校验
```

### 5.3 错误重试机制

```c
// 添加带重试的传感器读取函数
static int sensor_read_with_retry(
    int (*read_func)(int32_t*, int32_t*),
    int32_t *val1, int32_t *val2,
    int max_retries, int delay_ms)
{
    for (int i = 0; i < max_retries; i++) {
        int ret = read_func(val1, val2);
        if (ret == 0) {
            return 0;
        }
        if (i < max_retries - 1) {
            k_msleep(delay_ms);
        }
    }
    return -EIO;
}

// 使用示例
```
